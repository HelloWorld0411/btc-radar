# BTC 情报雷达

一个自己跑的机器人:每 5 分钟扫一遍全球新闻、币安公告、财经日历、链上大额转账和比特币价格,
只有**真正可能砸盘或拉盘的大事**才会推一条消息到你微信。

比如"特朗普撕毁伊朗停火协议"这种,它会推给你。

---

## 先说实话:它能做到什么,做不到什么

**已经验证过能用的**:

| 监控内容 | 数据源 | 实际延迟 |
|---|---|---|
| 地缘政治快讯 | 路透社、卫报、半岛电视台、BBC | 5 分钟 ~ 1 小时 |
| 特朗普发言/动作 | Truth Social 第三方镜像 | 30 分钟 ~ 3 小时 |
| 币安上币/下架公告 | 币安官方接口 | 几分钟 |
| 宏观数据(CPI/FOMC/非农) | 财经日历 | 公布前 20 分钟预警 |
| 比特币剧烈波动 | 币安行情 | 5 ~ 20 分钟 |
| 链上大额转账 | 比特币内存池 | 几分钟 |

**必须知道的三件事**:

1. **它不是"第一手",是"第二手里最快的免费方案"。** 消息从发生到你手机上,真实延迟是
   5 分钟到半小时。想做到真正第一手(秒级),只有两条路:买彭博/路透终端,或者花钱订阅
   专业快讯 API。免费方案的上限就在这里。

2. **GitHub 的定时任务不精确。** 它写着每 5 分钟跑一次,但在整点等高峰时段,
   GitHub 自己可能会延迟 5~20 分钟。这是 GitHub 的限制,改不了。

3. **关键词过滤有天花板。** 它靠"宣战/空袭/制裁/下架"这类词来判断重要性,
   偶尔还是会漏掉措辞含蓄的大新闻,或者推一条你其实不关心的。
   文件最后有一节讲怎么调,以及怎么用 AI 再过滤一遍把准确率拉上去。

## 准备阶段(10 分钟)

### 第 1 步:注册 PushPlus 并**完成实名认证**

这一步是最多人卡住的地方,**不实名认证的话消息一条都发不出去**。

1. 打开 <https://www.pushplus.plus>
2. 点右上角"登录",用**微信扫码**登录
3. 登录后去 <https://verify.pushplus.plus> 完成**手机号实名认证**
   —— 不做这一步,接口会返回错误码 `905`,消息发不出来
4. 回到网站,进入**个人中心**,复制那一长串**令牌(token)**,先存到记事本里

> 免费额度:每天 200 条消息,每分钟最多 5 条。我们每天最多用 6 条,够用。

### 第 2 步:注册 GitHub 账号

如果没有,去 <https://github.com> 注册一个,免费。

## 部署阶段(10 分钟)

### 第 3 步:新建一个**公开(Public)**仓库

1. 登录 GitHub,点右上角 `+` → `New repository`
2. 仓库名填 `btc-radar`
3. **可见性必须选 `Public`** ← 这一步很关键,原因见下面的注意事项
4. 勾选 `Add a README file`(随便有个文件就行)
5. 点 `Create repository`

> **为什么要选 Public?**
> GitHub Actions 对私有仓库每月只免费 2,000 分钟。我们的任务是每 5 分钟跑一次,
> 每次至少按 1 分钟计费 = 每月约 8,640 分钟,**一周就会用完**。
> 公开仓库的 Actions 是无限免费的。
> 你的令牌存在 GitHub Secrets 里,不会公开,代码公开没有任何风险。
> 如果你坚决要私有仓库,就把 `radar.yml` 里的 `*/5` 改成 `*/30`(半小时一次),
> 用量就降下来了,代价是消息慢半小时。

### 第 4 步:上传文件

把 `btc-radar` 文件夹里的**以下 4 项**拖到这个新仓库的网页上:

```
radar.py
config.yaml
requirements.txt
state.json
.github          ← 整个文件夹一起拖(里面有 workflows/radar.yml)
```

具体操作:在仓库页面点 `Add file` → `Upload files`,然后把上面这 4 项
**从 btc-radar 文件夹里面选中**拖进浏览器窗口,最后点 `Commit changes`。

> **⚠️ 最容易出错的地方:**
> 一定要拖**文件夹里面的东西**,而不是拖 `btc-radar` 文件夹本身。
> 如果拖了整个文件夹,文件会变成 `btc-radar/radar.py`,
> 而 GitHub 只认仓库根目录下的 `.github/workflows/`,定时任务就永远不会跑。
>
> 上传完请检查:仓库首页应该能直接看到 `radar.py`,点进 `Actions` 标签页
> 能看到一个叫「BTC 情报雷达」的任务。如果看不到,说明路径不对。

**如果 `.github` 文件夹没拖上去**(有些浏览器会忽略点开头的文件夹),手动建:

1. 仓库页面点 `Add file` → `Create new file`
2. 文件名那里**直接输入** `.github/workflows/radar.yml`(斜杠会自动变成文件夹)
3. 打开本地的 `radar.yml`,把内容全部复制粘贴进去
4. 拉到最下面点 `Commit changes`

### 第 5 步:填入你的令牌

1. 仓库页面点 `Settings`(顶部菜单)
2. 左侧栏找到 `Secrets and variables` → `Actions`
3. 点绿色按钮 `New repository secret`
4. `Name` 填:`PUSHPLUS_TOKEN`(必须一字不差)
5. `Secret` 填:第 1 步复制的那个令牌
6. 点 `Add secret`

### 第 6 步:手动跑一次测试

1. 点仓库顶部的 `Actions` 标签
2. 左侧点「BTC 情报雷达」
3. 右边有个 `Run workflow` 按钮,点开,把模式选成 **`test`**,再点绿色的运行按钮
4. 等 30 秒左右刷新页面,点进这次运行记录
5. **看你的微信** —— 应该收到一条「【雷达】测试推送成功」

**没收到?** 看运行记录里 `运行雷达` 那一步的输出:

| 日志里的错误 | 意思 | 怎么办 |
|---|---|---|
| `code=905` | 没做实名认证 | 去 verify.pushplus.plus 认证 |
| `code=903` | 令牌填错了 | 回 PushPlus 个人中心重新复制 |
| `code=900` | 今日额度用完 | 明天再试 |
| `没有设置 PUSHPLUS_TOKEN` | Secret 名字写错了 | 检查是不是拼成了别的 |

**只看到标题、点进去才看到正文?** 这是微信的限制。解决办法:在微信里找到
PushPlus 公众号,给它发一条「**激活消息**」,之后 24 小时内的消息正文会直接显示。

### 完成

测试通过后,**把 `Run workflow` 的模式改成 `normal` 再跑一次**。
第一次正常运行只会安静地记录一条基线(不推送),之后就自动进入每 5 分钟一次的循环。

以后你什么都不用做了。

## 日常使用

### 收到的消息长什么样

```
【雷达】路透社: Trump says US is tearing up the Iran ceasefire deal, orders strikes

## 情报雷达 · 1 条

1. [路透社] Trump says US is tearing up the Iran ceasefire deal, orders strikes
   `09-19 22:14 · 评分 23 · 决定性:ceasefire, 相关:trump/iran`
   [查看原文](https://...)

---
今日已推 2/6 条 · 阈值 12
```

一轮里抓到多条会**打包成一条**推送,不会连着响好几次手机。

### 觉得太吵 / 太安静?改 `config.yaml`

在 GitHub 网页上点开 `config.yaml`,点右上角的铅笔图标就能直接编辑,
改完点 `Commit changes`,下一轮就生效。

最常用的三个旋钮:

| 想干什么 | 改哪个 |
|---|---|
| **整体太吵** | `threshold` 从 `12` 调到 `14` 或 `16`,或者把 `max_pushes_per_day` 调到 `3` |
| **整体太安静,怕漏** | `threshold` 调到 `10`,`max_pushes_per_day` 调到 `12` |
| **不想收链上巨鲸** | `whales` 下面的 `enabled` 改成 `false` |
| **不想收币安公告** | `binance_announcements` 下面的 `enabled` 改成 `false` |
| **只想盯特朗普和地缘政治** | 把 `feeds` 里几个币圈媒体的 `enabled` 改成 `false` |
| **价格波动阈值太高/太低** | `price` 下面的 `move_15m_pct`(默认 2.5 表示 15 分钟涨跌 2.5% 才报) |
| **想推给多个人** | 在 PushPlus 建一个"普通群组",把群组编码填到 `push.topic` |

### 想再加自己的关键词

`config.yaml` 里 `scoring` 下面有三个词表,直接往里面加就行:

- `decisive` —— 加进去,够了门槛就一定推(最高优先级)
- `critical` —— 需要有国家/机构/币种词配合才会推
- `exclude` —— 加进去的词,命中就直接丢弃

词尾写 `*` 表示前缀匹配,比如 `delist*` 能命中 delist / delisted / delisting。

## 提高准确率(可选)

关键词过滤的天花板就在这里。如果你愿意花一点点钱,可以开启 AI 二次过滤:

1. 去 <https://console.anthropic.com> 申请一个 API Key
2. GitHub 仓库 `Settings` → `Secrets and variables` → `Actions` → 新建 Secret,
   名字填 `ANTHROPIC_API_KEY`,值填你的 Key
3. 编辑 `config.yaml`,把最后一行的 `llm_filter.enabled` 改成 `true`

开启后,分数卡在门槛附近的模糊消息会额外交给 AI 判断一次"这条值不值得叫醒你",
明显更准。成本大约是**每天几分钱**。API 调用失败会自动退回关键词判断,不会漏消息。

> 注意:`llm_filter.model` 那一行填的模型名要确保你的账号能用。
> 如果日志里出现调用失败,换成你账号里可用的模型名即可。

## 常见问题

**Actions 页面好多个红色的 ❌**
点进去看是哪一步红的。绝大多数是网络抖动 —— 某个新闻源临时挂了。
单个源失败不影响其他源,下一轮会自动恢复,不用管。
只有 `保存去重记录` 那一步连续失败才需要关注(会导致重复推送)。

**仓库里一直冒出 `chore: 更新雷达状态` 的提交**
这是正常的,它在记录"哪些消息已经推过了",不然每次运行都会重复推给你。
顺便还有个好处:GitHub 会把 60 天没动静的仓库的定时任务自动停掉,
而我们的提交让仓库一直有活动,所以不会被杀。

**我想改运行频率**
编辑 `.github/workflows/radar.yml`,把 `cron: "*/5 * * * *"` 里的 `5` 改成别的数字
(注意:必须是 5 的倍数以外的也行,但 GitHub 最小间隔就是 5 分钟)。

**想让消息更快**

三个升级方向,按性价比排序:

1. **换 Cloudflare Workers**(仍然免费):它支持 1 分钟一次的定时任务,
   而且是边缘节点,比 GitHub Actions 稳定,延迟能从 5~20 分钟降到 1~5 分钟。
2. **租一台最便宜的 VPS**(约 ¥10~20/月):跑 `python radar.py` 挂个 systemd 定时器,
   延迟最低、最可控。
3. **买付费新闻 API**:这是唯一能把延迟压到秒级的办法,但成本从每月几十到上千美元不等。

现在的架构改这几种都很容易 —— `radar.py` 就是一个普通 Python 脚本,
拿到哪儿都能跑,只有 `PUSHPLUS_TOKEN` 一个环境变量是必须的。

## 文件说明

| 文件 | 干什么的 | 你要不要动 |
|---|---|---|
| `radar.py` | 主程序,抓取+打分+推送 | 不用动 |
| `config.yaml` | **所有可调参数都在这里** | 需要调灵敏度时改这个 |
| `requirements.txt` | 依赖清单 | 不用动 |
| `state.json` | 自动维护的去重记录 | 不用动 |
| `.github/workflows/radar.yml` | 定时任务配置 | 改运行频率时动 |
