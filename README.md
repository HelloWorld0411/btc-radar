# BTC 情报雷达

一个自己跑的机器人:每 5 分钟扫一遍全球新闻、币安公告、财经日历、链上大额转账和比特币价格,
筛出**可能砸盘或拉盘的大事**,再加上市场情绪指标和利好利空判断,推一条消息到你微信。

---

## 先说清楚它有边界

**已实测能用的**:

| 监控内容 | 数据源 | 实际延迟 |
|---|---|---|
| 地缘政治快讯 | 路透社、卫报、半岛电视台、BBC | 5 分钟 ~ 1 小时 |
| 特朗普发言/动作 | Truth Social 第三方镜像 | 30 分钟 ~ 3 小时 |
| 币安上币/下架公告 | 币安官方接口 | 几分钟 |
| 宏观数据(CPI/FOMC/非农) | 财经日历 | 公布前 20 分钟预警 |
| 比特币剧烈波动 | 币安行情 | 5 ~ 20 分钟 |
| 链上大额转账 | 比特币内存池 | 几分钟 |
| 市场情绪 | 恐惧贪婪指数、合约指标、ETF 资金流 | 实时 / 每日 |

**三件必须知道的事**:

1. **它不是"第一手",是"第二手里最快的免费方案"。** 消息从发生到你手机,真实延迟 5 分钟到半小时。
   想秒级只有彭博终端或付费快讯 API,免费方案的上限就在这里。

2. **GitHub 定时任务不精确。** 写着 5 分钟一次,但高峰时段 GitHub 自己会延迟 5~20 分钟,改不了。

3. **它给的是判断材料,不是投资建议。** 机器人会告诉你"这条消息是利空、传导机制是什么",
   以及"当前指标显示短期偏空"。**它不会告诉你买还是卖、买多少、在哪个点位进出。**
   这不是推脱 —— 一个靠关键词和指标的机器人输出"现在做多",会带着虚假的确定性,
   拿它去动真金白银比没有信号更危险。你把材料看全了,结论自己就出来了。

## 准备阶段(约 15 分钟)

### 第 1 步:注册 PushPlus 并**完成实名认证**

**不实名认证的话消息一条都发不出去**,这是最多人卡住的地方。

1. 打开 <https://www.pushplus.plus>,点右上角"登录",用**微信扫码**登录
2. 登录后去 <https://verify.pushplus.plus> 完成**手机号实名认证**
3. 回到网站,进入**个人中心**,复制那串**令牌(token)**存到记事本

> 免费额度:每天 200 条消息。我们每天最多用 6 条。

### 第 2 步:申请 Anthropic API Key(用于判断利好利空)

1. 打开 <https://console.anthropic.com> 注册
2. 在 **Billing** 里充值(最低 $5,按用量扣,这个机器人每天大约花几分钱)
3. 在 **API Keys** → `Create Key`,复制出来的 `sk-ant-` 开头的那串,存好
   —— 这串只显示一次,关掉页面就看不到了

> 不想花钱也行:把 `config.yaml` 里 `ai.enabled` 改成 `false`。
> 机器人照样跑,消息照样推,只是没有利好利空判断和多空倾向解读,只有原始指标。

### 第 3 步:注册 GitHub 账号

去 <https://github.com> 注册,免费。

## 部署阶段(约 15 分钟)

### 第 4 步:新建一个**公开(Public)**仓库

1. 点右上角 `+` → `New repository`
2. 仓库名填 `btc-radar`
3. **可见性必须选 `Public`**
4. 勾选 `Add a README file`
5. 点 `Create repository`

> **为什么必须 Public?**
> GitHub Actions 对私有仓库每月只免费 2,000 分钟。我们每 5 分钟跑一次,
> 每次至少按 1 分钟计费 = 每月约 8,640 分钟,**一周就烧完**。公开仓库无限免费。
> 你的两个密钥都存在 GitHub Secrets 里,不会公开,代码公开没有任何风险。
> 坚决要私有的话,把 `radar.yml` 里的 `*/5` 改成 `*/30`(半小时一次),用量就降下来了。

### 第 5 步:上传文件

在仓库页面点 `Add file` → `Upload files`,把 `btc-radar` 文件夹里的这 5 项
**从文件夹里面选中**拖进浏览器:

```
radar.py
config.yaml
requirements.txt
state.json
.github          ← 整个文件夹,里面有 workflows/radar.yml
```

然后点 `Commit changes`。

> **⚠️ 最容易出错的地方**
> 一定要拖**文件夹里面的东西**,不要拖 `btc-radar` 文件夹本身。
> 拖错了路径会变成 `btc-radar/radar.py`,而 GitHub 只认仓库根目录的
> `.github/workflows/`,定时任务永远不会跑 —— 而且不会有任何报错提示。

**如果 `.github` 没上传成功**(浏览器经常忽略带点的文件夹),手动建:

1. 点 `Add file` → **`Create new file`**(注意是 Create,不是 Upload)
2. 文件名那一栏**直接输入** `.github/workflows/radar.yml`,打斜杠时它会自动变成文件夹
3. 打开本地 `radar.yml`,内容全部复制粘贴进去
4. 拉到底点 `Commit changes`

**另一种改法**:如果你已经把 `radar.yml` 传到了根目录,点开它 → 点右上角铅笔图标 →
把最上面文件名栏改成 `.github/workflows/radar.yml` → 提交。GitHub 会自动把它移过去。

上传完检查:仓库首页应该能直接看到 `radar.py`,点顶部 `Actions` 标签,
左侧能看到一个叫「**BTC 情报雷达**」的任务。看不到就是路径不对。

### 第 6 步:填入两个密钥

仓库页面点 `Settings` → 左侧 `Secrets and variables` → `Actions` → `New repository secret`,
加两个:

| Name | Secret | 必填? |
|---|---|---|
| `PUSHPLUS_TOKEN` | 第 1 步复制的令牌 | 必填 |
| `ANTHROPIC_API_KEY` | 第 2 步复制的 `sk-ant-` 开头那串 | 想用 AI 分析就填 |

名字必须一字不差。没填 `ANTHROPIC_API_KEY` 也不会报错,只是没有 AI 分析。

### 第 7 步:跑一次自检

1. 点仓库顶部 `Actions` 标签 → 左侧点「BTC 情报雷达」
2. 右边 `Run workflow` 按钮,模式选 **`test`**,点绿色运行按钮
3. 等 30 秒刷新,点进这次运行记录
4. **看你的微信** —— 会收到一条自检报告,上面逐项写着哪几项通过

自检会检查三项:PushPlus 令牌、市场情绪接口、AI 分析。哪项挂了日志里会直接写明原因。

| 日志里的错误 | 意思 | 怎么办 |
|---|---|---|
| `code=905` | 没做实名认证 | 去 verify.pushplus.plus 认证 |
| `code=903` | 令牌填错了 | 回 PushPlus 个人中心重新复制 |
| `没读到 ANTHROPIC_API_KEY` | Secret 名字拼错了,或没加 | 检查 `Settings` → `Secrets` |
| `AI 调用失败 401` | API Key 无效或余额不足 | 去 console.anthropic.com 检查 |
| `市场情绪 X/5 项可用` | 部分接口临时抽风 | 正常现象,不影响使用 |

**只看到标题、点进去才看到正文?** 这是微信的限制。在微信里找到 PushPlus 公众号,
给它发一条「**激活消息**」,之后 24 小时内的消息正文会直接显示。

### 第 8 步:正式启动

把 `Run workflow` 的模式改回 **`normal`** 再跑一次。首次正常运行只会安静地建一条基线,
之后就自动进入每 5 分钟一次的循环。以后你什么都不用管了。

## 怎么看那几个指标

这一节值得花两分钟读,比记一堆规则有用。

**恐惧贪婪指数(0-100)**:市场情绪温度计。低于 25 是极度恐慌,历史上常对应阶段性底部;
高于 75 是极度贪婪,往往是局部顶。注意它是**反向参考** —— 极端值比中间值有信息量。

**资金费率**:合约市场里多头付给空头的钱。为正说明多头愿意付钱做多(多头拥挤),
越高越危险;转为明显的负值说明空头拥挤,反而容易挤空上涨。**关键不是绝对值,是它和近 7 日均值的偏离。**

**多空账户比**:多少比例的账户在做多。大于 1 说明多数人在做多。
它本身不是方向信号,但**创月高/月低**的时候值得警惕 —— 大众一致的时候通常不是好时候。

**未平仓合约量(OI)**:市场上还没平掉的合约总量。**要和价格一起看**:
价格涨+OI 涨 = 新资金进场做多(健康);价格涨+OI 跌 = 空头回补(虚涨,持续性差);
价格跌+OI 涨 = 新空头进场(下跌趋势可能延续)。

**ETF 净流入**:中长线最重要的资金面证据。看的是**趋势和斜率**,不是单日数字 ——
连续三天净流出比单日大额流出更值得注意。数据一天更新一次,所以代码里缓存了 6 小时。

**矛盾信号**那一行是我特意让 AI 输出的:指标互相打架的时候,往往比一致的时候更有信息量,
因为那通常意味着市场处在转折期。

## 日常调参

改 `config.yaml`(在 GitHub 网页上点开文件 → 点铅笔图标 → 改完点 `Commit changes`)。

| 想干什么 | 改哪里 |
|---|---|
| **整体太吵** | `scoring.threshold` 从 `12` 调到 `14`、`16`;或 `push.max_pushes_per_day` 调到 `3` |
| **整体太安静,怕漏** | `scoring.threshold` 调到 `10`;`max_pushes_per_day` 调到 `12` |
| **想完全关掉 AI 省钱** | `ai.enabled` 改成 `false` |
| **想让 AI 管得更多(更容易否掉边缘消息)** | `ai.borderline_band` 从 `10` 调到 `14` |
| **觉得 AI 太爱否消息** | `ai.borderline_band` 调到 `6` 或 `0`(0 = AI 只做标注,不否消息) |
| **不想收链上巨鲸** | `whales.enabled` 改成 `false` |
| **不想收币安公告** | `binance_announcements.enabled` 改成 `false` |
| **只想盯特朗普和地缘政治** | 把 `feeds` 里几个币圈媒体的 `enabled` 改成 `false` |
| **不想收情绪面板,只要消息** | `sentiment.enabled` 改成 `false` |
| **价格异动太敏感** | `price.move_15m_pct` 从 `2.5` 调大(单位是百分比) |
| **推给多个人** | 在 PushPlus 建"普通群组",编码填到 `push.topic` |
| **改免责声明文字** | `push.disclaimer` |

**想改判重标准**:`scoring` 下面有三个词表,直接往里面加。
`decisive` 是加了一定推的高置信短语,`critical` 是需要配合实体词的事件词,
`exclude` 是命中就丢。词尾写 `*` 表示前缀匹配(`delist*` 命中 delist/delisted/delisting)。

## 常见问题

**Actions 页面出现红色的 ❌**
点进去看哪一步红的。绝大多数是网络抖动 —— 某个新闻源临时挂了。
单个源失败不影响其他源,下一轮自动恢复。**AI 调用失败也不会丢消息**,
消息照常推,只是少一段分析。只有 `保存去重记录` 连续失败才需要管。

**仓库里一直冒出 `chore: 更新雷达状态` 的提交**
正常。它在记录"哪些消息推过了",不然每次都重复推给你。
顺带一个好处:GitHub 会把 60 天没动静的仓库的定时任务自动停掉,而这些提交让它一直有活动。

**AI 分析的费用到底多少**
每次推送最多调 2 次(一次批注消息、一次解读情绪),每天最多 6 次推送。
用的是最便宜的模型档位。实际大约每天几分钱人民币。

**模型名会不会过期**
不会。代码会先问 Anthropic 要一份"你现在有哪些模型"的列表,自动挑一个便宜的档位,
并记在 `state.json` 里。真遇到模型下线,它会自动重新探测并换一个,你不用管。

**想让消息更快**
1. **换 Cloudflare Workers**(仍免费):支持 1 分钟一次,延迟能降到 1~5 分钟。
2. **租最便宜的 VPS**(约 ¥10~20/月):延迟最低最可控。
3. **买付费新闻 API**:唯一能把延迟压到秒级的办法。
`radar.py` 就是个普通 Python 脚本,拿到哪儿都能跑,只有两个环境变量是必须的。

## 文件说明

| 文件 | 干什么的 | 要不要动 |
|---|---|---|
| `radar.py` | 主程序:抓取 + 打分 + 情绪 + AI 分析 + 推送 | 不用动 |
| `config.yaml` | **所有可调参数都在这里** | 调灵敏度时改这个 |
| `requirements.txt` | 依赖清单 | 不用动 |
| `state.json` | 自动维护的去重记录、接口缓存、AI 模型名 | 不用动 |
| `.github/workflows/radar.yml` | 定时任务配置 | 改运行频率时动 |
